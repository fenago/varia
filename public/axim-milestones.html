How VARIA fits

VARIA is not just one more authentic assessment. It is the trust layer the cohort's own framing requires and nobody else in the cohort is likely to bring.

Application over recall.Every VARIA blueprint is a performance task with an analytic rubric. There is no recall item type in the system.
How over what.Rubric criteria score process (evidence, prioritisation, reasoning under shift), and each student's adapted model answer lets faculty grade the reasoning path, not a fixed key.
Employer-valued.The surface dimensions (domain, stakeholder, scenario) are exactly where employer partners plug in. An employer contributes real scenarios and stakeholder roles, and every student gets a workplace-shaped task.
Evidence all parties can trust.The four integrity checks and the compliance console are the mechanism. If assessments become personalised and AI-generated, every partner will be asked "how do you know two students got an equivalent task?" VARIA is the only answer in the room with a benchmark behind it.
Portable signal.A released variant set plus its integrity report is a defensible artifact: the task, the rubric, the score, and the equivalence evidence travel together.

Honest gaps to name before someone else does

  • No employer-facing role or validation workflow yet. Employer validation happens outside the tool today.
  • No learner-facing delivery. Students receive tasks through Canvas, not VARIA. Canvas integration is a disabled button.
  • Rubric stability (P3) is a proxy. The full protocol is pre-registered, not built.
  • Outcomes instrumentation (engagement, time on task, persistence) is not collected by the app.
  • Live generation at class scale has been tested in demo mode only.

Outcomes the app produces natively

  • Rubric scores by criterion and score spread by version (student mastery).
  • Integrity report per set and audit trail (institution, employer trust).
  • Difficulty appeals count: zero on a released set is a headline.
  • Blueprints as portable JSON: the "shared assets adopted by 15+ institutions" path.

Finalise employer validation approach
  • Employers validate the surface dimensions and the rubric, not each variant. They supply scenarios, stakeholder roles and complaint triggers, and sign off that the rubric reflects what they hire for.
  • Offer a one-page employer validation checkpoint export: construct, rubric, scenario bank.
  • Ask whether the cohort has a shared employer sign-off form so MDC does not invent one.
Nov 2026 Due
Conduct employer validation checkpoint
  • Run one employer session on the demo run: three versions side by side, "would you accept any of these as a work sample?"
  • Capture their edits as new surface dimension values. That is the validation loop made concrete.

  • Integration is a strength: static site, no server, no institutional data leaves the browser, faculty bring their own key. Nothing for MDC IT to host.
  • Documentation to submit: architecture spec, deployment README, integrity report CSV as the data artifact format.
  • Name the Canvas gap and the plan: per-student assignment export in December; LTI or Canvas API in the pilot cycle if the cohort wants it.
Q1–Q2 2027 · Pre-pilot, pilot, evaluation
Jan 2027 Pre-pilot feedback session: soft launch, faculty demo or employer demo
  • Offer to be the cohort's faculty demo. The demo run needs no key and no setup.
  • Ask peers to try Import with their own assignment sheet: the fastest way to surface extraction failures.
Feb 2027 Finalise prototype: onboard faculty, configure courses, complete QA
  • Onboarding is the five-step Getting started page. Target: a colleague goes from upload to released set in under 20 minutes without training.
  • QA gate: live generation on all three blueprints with real keys and a real roster; every set clears P1, P2, P4.
  • Set the threshold profile with the assessment office and record it on the compliance console before pilot.
Mar 2027 Due
Begin pilot
  • Two sections, one receiving variants and one the fixed task, same rubric. That yields the persistence-correlation and mastery comparisons the framework asks for.
  • Record the baseline: prior-term scores on the same assignment.
Apr 2027 Continue pilot; at least one student and one employer validation checkpoint
  • Student checkpoint: the "not a test" rate and self-efficacy items, plus two questions on perceived fairness of their version, VARIA's specific claim.
  • Employer checkpoint: review a stratified sample of graded submissions across versions.
  • Appeals are a built-in metric. Zero difficulty appeals on a released set is a headline.
May 2027 Close pilot; collect data; begin evaluating student outcomes
  • Native data: rubric scores by criterion, score spread by version, reading ease per version, integrity reports, audit trail.
  • Collected outside: engagement, time on task, persistence, satisfaction.
  • The paper's pre-registered follow-up (rubric stability, copy resistance) can be the evaluation design, turning the pilot into a publishable second study.
Jun 2027 Due
Submit all final artifacts from validation loops, outcomes and evaluations
  • Artifacts: blueprints, released variant sets, integrity reports, rubric, employer validation records, evaluation write-up, and the app itself as an open asset.
Q3 2027 · Blueprint feedback, scale and sustain
Jul 2027 Provide feedback on the v1 blueprint
  • Propose that the cohort's shared rubric (faculty practice outcome, validated across 3+ institutions) be authored as a VARIA blueprint so validation and variation share one format.
Aug–Sep 2027 Share the final blueprint; support conversations to extend and scale
  • Scale story: a static site any institution deploys in minutes, and blueprints are portable JSON. That is the "15+ institutions using shared assets" metric with a concrete path.

Technical constraints
None on hosting. Constraints are API cost per run, faculty holding their own keys, and no LMS integration yet.
Unresolved, needs support
Canvas delivery of per-student tasks; institutional guidance on AI API use with student-identifying rosters.
Biggest risk to a March 2027 live pilot
Getting personalised tasks into students' hands inside the LMS with grades flowing back. Mitigation: a December decision between manual per-student export and an LTI build, and IT sign-off secured by January.

One strategic note

The cohort framework assumes AI-enhanced assessments are trustworthy. The paper shows that assumption is conditional, and VARIA is the instrument that makes it checkable. Position MDC's contribution as the cohort's integrity infrastructure, not only its pilot. That is a role no other partner is set up to play, and it maps to three required outcomes at once: shared assets adoption, employer validation, and a shared rubric across institutions.
