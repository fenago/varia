Analysing the submissions
Grade against the adapted model answer
Each student's version has its own expert answer, rewritten into their scenario. Compare to that, not to the original.
Watch the score spread by version
If one version's mean score sits well below the rest, that is evidence the difficulty check missed something. The roster flags it for you.
Handle appeals with the numbers
A student claiming an unfair version gets a documented answer: their version's reading ease against the set mean, on the record.
Two identical submissions are now meaningful
Because no two students received the same task, matching answers are a finding rather than a coincidence.
Common questions
Do I have to rewrite my rubric?
No. The rubric is what is held constant — it is the thing the checks are protecting.
What if I don't trust a version?
Reject and regenerate any single version before release. Rejections are logged with your reason.
Is this proctoring?
No. Nothing monitors the student. The task design is what makes sharing answers unproductive.
Can I reuse a set next term?
Yes, but the library will prompt you to regenerate — released tasks circulate.

The system can draft one from your rubric for you to correct. It is required: the rubric-stability check works by adapting your answer into each student's scenario.

These mockups turn the VARIA benchmark into a working product: a professor authors one assessment blueprint, the system generates a different-looking task for every student, and nothing is released until the variant set passes the paper's four integrity properties. Oversight roles get the same numbers, aggregated.

Assumption 01
The professor never sees a threshold unless something fails

Plain-language labels carry the interface — "Do the versions look different enough?" — with the paper's metric names (cosine, σFlesch, τdiv) available on hover. Failures are the only place numbers lead.

Assumption 02
All four properties must pass individually

The composite score J is shown for comparison across runs, but release is gated on four separate pass checks, not on the average. A set can average 0.86 and still be unreleasable.

Assumption 03
Prompting strategy is an operating point, not a setting

The paper finds no dominant strategy, so the generation step asks what the course is protecting against — construct fidelity or copy-paste — and maps that to zero-shot / structured CoT versus few-shot / dimension-preserving.

Assumption 04
Rubric stability is flagged as a proxy

P3 is currently readability dispersion of the canonical solution, not full rubric re-application. The UI labels it provisional so an institution never over-reads it.
